# PROJECT RULES

1. **DO NOT MODIFY ANYTHING IN `./data/`**:
   - The `./data/` directory contains local runtime state generated by Docker containers (OpenSible and LocalStack).
   - Under NO circumstances should any agent or tool read, write, edit, or delete files inside `./data/`.
   - All configuration and code edits must be performed strictly in workspace repository source files (e.g. `envs/`, `docker-compose.yml`, `.gitignore`, `README.md`).

2. **DO NOT EXECUTE COMMANDS INSIDE DOCKER CONTAINERS (`docker exec`)**:
   - Under NO circumstances should any agent run `docker exec` commands to modify runtime state, files, or processes inside running containers.
   - All operations must be driven via source code (GitOps), standard Docker Compose management, or the OpenSible/LocalStack Web UI.

### TROUBLESHOOTING EXCEPTIONS
*If a playbook is stuck in "RUNNING" state due to a bug in the project and blocks other playbooks from running, you may run the following commands to forcefully clear the ghost state in both the database and the UI:*

**1. Clear backend worker lock (Database):**
```bash
docker exec opensible-server python -c "import sqlite3; conn = sqlite3.connect('/app/data/index.db'); conn.execute('DELETE FROM running_executions;'); conn.commit()"
```

**2. Fix the UI display (JSON files):**
```bash
find data/opensible/projects -type f -path "*/history/executions/*.json" -exec sed -i 's/"status": "RUNNING"/"status": "FAILED"/g' {} +
```

### PLAYBOOK PRE-FLIGHT VERIFICATION

**10. Ansible syntax-check (bash) — run in temporary container without altering project containers:**
```bash
docker run --rm -v "$(pwd -W 2>/dev/null || pwd):/w" -w /w --entrypoint /bin/sh alpine/ansible -c '
for f in playbooks/*.yml; do
  printf "  %-30s " "$(basename $f)"
  ansible-playbook --syntax-check -i localhost, "$f" >/dev/null 2>&1 && echo OK || echo ERROR
done'
```

> **Validating YAML syntax alone is INSUFFICIENT.** A playbook may parse as valid YAML but fail when Ansible parses tasks. For example: a line continuation backslash `\` inside a double-quoted string can cause Ansible's `split_args()` to treat the quote as unclosed, resulting in `unbalanced jinja2 block or quotes` pointing misleadingly to the TASK NAME instead of the offending line.
>
> Rule: **do not use line-continuation `\` within double-quoted strings** in the `shell` module.

### SECRETS

**`.env` is the ingestion source, not where playbooks read from.** `playbooks/1.manage-secrets.yml` reads `GITHUB_TOKEN` from `.env` and pushes it to AWS Secrets Manager (`learn-opensible/github-token`). Other playbooks and CodeBuild do NOT read `.env` — they fetch from Secrets Manager using IAM credentials. To rotate tokens: update `.env` → `docker compose up -d opensible-worker` → re-run `1.manage-secrets.yml`. See README §8.

**8. Check secret existence (bash) — metadata only, never prints secret value:**
```bash
docker exec opensible-worker sh -c '
  aws secretsmanager describe-secret --secret-id learn-opensible/github-token \
    --endpoint-url http://localstack:4566 \
    --query "{Name:Name,ARN:ARN,Changed:LastChangedDate}" --output table
'
```

**9. View secret versions (rotation creates a new version; older version is tagged AWSPREVIOUS):**
```bash
docker exec opensible-worker sh -c '
  aws secretsmanager list-secret-version-ids --secret-id learn-opensible/github-token \
    --endpoint-url http://localstack:4566 \
    --query "Versions[].{Version:VersionId,Stages:VersionStages}" --output table
'
```

> **Never run `get-secret-value` manually.** It exposes tokens to terminal logs and scrollback history.

> LocalStack clears runtime state upon container restart, **including secrets**. Re-run `1.manage-secrets.yml` after resetting containers.

### ARGOCD

**6. Retrieve ArgoCD admin password (bash):**
```bash
docker exec opensible-worker sh -c '
  kubectl() { /usr/local/bin/kubectl --kubeconfig /root/.kube/config "$@"; }
  kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo
'
```
> Note on Git Bash on Windows: wrap commands in `sh -c '...'` to avoid MSYS converting `/usr/local/bin/kubectl` into `C:/Program Files/Git/usr/local/bin/kubectl`.
- User is `admin`. Access UI via port-forward or dedicated ALB hostname:
  ```bash
  # kubeconfig for Windows host: copy from worker and point server to https://127.0.0.1:4510
  docker exec opensible-worker cat /root/.kube/config > "$env:USERPROFILE\.kube\localstack-eks"

  kubectl --kubeconfig "$env:USERPROFILE\.kube\localstack-eks" \
    port-forward -n argocd svc/argocd-server 8080:80
  # → http://localhost:8080
  ```
- The secret `argocd-initial-admin-secret` is created on initial installation and deleted automatically after password changes.
- `3.deploy-k8s-infra.yml` prints access credentials upon completion.

**7. Check sync status of ALL Applications (bash):**
```bash
docker exec opensible-worker sh -c '
  kubectl() { /usr/local/bin/kubectl --kubeconfig /root/.kube/config "$@"; }
  kubectl -n argocd get applications \
    -o custom-columns="NAME:.metadata.name,OWNER:.metadata.ownerReferences[0].kind,SYNC:.status.sync.status,HEALTH:.status.health.status,PATH:.spec.source.path"
  kubectl -n devops-apps get deploy,pods
'
```
- **PATH** column must be a STRING. If formatted as `map[basename:... segments:...]`, check the reserved `path` keyword gotcha below.
- **OWNER** column must be `ApplicationSet`.
- `REVISION` matches the latest commit on `main`. Click **Refresh** in the ArgoCD UI to trigger an immediate cache refresh.

### APPLICATIONSET

**11. `path` is a RESERVED KEYWORD in git files generator — do not use it in `config.yaml`.**

The generator inserts an object named `path` representing the location of `config.yaml` (`.path.path`, `.path.basename`, `.path.segments`...), overwriting custom keys of the same name:

```
spec.source.path: "map[basename:devops-hello-world filename:config.yaml path:gitops/...]"
```

> The Application is created and shows `HEALTH: Healthy` (no resources to be unhealthy), but remains stuck on `SYNC: Unknown` without deploying resources.
>
> Use `manifestPath` instead of `path`.

**12. Handing over manual Applications to ApplicationSet: remove finalizers BEFORE deleting.**

```bash
# Correct handover: removes Application CR while preserving workloads
kubectl -n argocd patch application NAME --type=merge -p '{"metadata":{"finalizers":null}}'
kubectl -n argocd delete application NAME
```

> **`--cascade=orphan` DOES NOT protect resources.** That flag controls Kubernetes GC (`ownerReferences`). ArgoCD uses `resources-finalizer.argocd.argoproj.io`.
>
> Deleting without stripping finalizers causes ArgoCD to delete Deployments, Services, Ingresses, and Namespaces.

**13. Do not run `kubectl apply` manually on manifests under `gitops/platform/` or `gitops/workloads/` once ApplicationSet is active.**

ArgoCD manages them and `selfHeal: true` will revert manual edits. Commit changes to git instead. Playbooks manage `gitops/bootstrap/`, Secrets, and ALB target registration.
